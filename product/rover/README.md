# Product viewer

The static Product page mounts this isolated React / R3F island only at widths of 1024px and above. It uses React, Three.js, React Three Fiber and GSAP ScrollTrigger, built with esbuild; no external services, environment maps or decoder downloads are needed.

`stages.js` holds the five visible configuration names and descriptions. `flow.js` defines a deterministic arrival / docking / work / departure timeline and fixed mount coordinates. `Attachments.jsx` supplies procedural implement geometry; `Hitch.jsx` contains the three-point hitch. `Arms.jsx` builds the two rear-mounted manipulators with tapered cast links, coaxial hinge bearings, wrist/tool flanges and slotted parallel jaws. Rigid parts are merged by finish to keep their bolts, seals and cable detail within the existing render budget. Arm motion follows the visible joint axes; the jaws close along their guides, with a small timing offset between the arms. `RoverCanvas.jsx` frames the assembly, loads the optimized model and renders on demand. `FarmWorld.jsx` adds a small feathered road patch with moving ruts. `FarmBackdrop.jsx` uses five locally hosted photographs: mango orchard, vineyard, wheat field, loading yard and warehouse floor. Images crossfade during travel from the same scroll progress as the rover, with subtle parallax and a restrained light overlay. It loads the current image first, then warms adjacent stages, retaining decoded images for backward scrolling. Photo credits and licenses are recorded in `assets/product/SOURCES.md`. Photos load only in desktop 3D mode. The moving farm ruts fade away for the industrial stages. The supplied assembled renders guide the arm housings, sprayer shell, hitch frame, extended tray and rectangular trolley; these remain illustrative geometry rather than CAD. `Cargo.jsx` adds six taped cartons inside the trolley, merged by finish to limit draw calls. `WorkActions.jsx` adds spray, hitch engagement, trolley coupling and harvest loading, while the arm joints and fan move in `RoverCanvas.jsx`. The camera keeps the same three-quarter viewing direction, distance, field of view and zoom across all five stages, so the rover stays the same apparent size with every attachment. The trolley uses a lateral framing offset to fit the trailer; the assembly does not move toward the camera or shrink. The rover heading stays fixed, with no turn or side swap. Travel, wheel angles, body bounce, environment parallax and tool actions are sampled entirely from scroll progress, so reverse scrolling restores the same scene. Travel distance is scaled to 60% for a calmer pace, with wheels and terrain kept in sync. The entire sequence spans 18 viewport heights (at least 12,600px), three times its original scroll range, so travel, docking and working actions all require more scrolling. The scrolling 3D view has no bottom progress or stage bar; the static poster fallback retains its stage controls. The rover and wheels stop during docking and working. Desktop resizes explicitly refresh the pin with smooth scrolling temporarily disabled during measurement; the normal scroll animation is unchanged. Wheel pivots in the supplied optimized model were estimated from assembly bounds, not verified CAD axle coordinates.

The final model is `assets/models/rover.glb` (93,747 triangles, 17 meshes, nine materials, four named wheel groups, Meshopt compressed). Poster images are in `assets/implements/assembled/`. Their public URLs remain `/models/rover.glb` and `/implements/assembled/*.webp`. Original CAD exports, KeyShot files, raw renders and one-off conversion tools have been removed from the source and are never published.

## Startup and fallbacks

1. The build bundles `prepaint.js` into a tiny head script. Its shared `graphics.js` decision checks viewport and reduced motion before probing graphics. Small screens never request a WebGL context.
2. On automatic desktop 3D startup, a head class hides the static viewer's contents while its CSS reserves the final viewer height. Other modes show `arms.webp`, which is also React's first poster.
3. `bootstrap.js` starts the desktop island near the viewport, loading its component and model manifest together. A failed component import restores the HTML fallback. A watchdog also releases the fallback if startup never completes.
4. The canvas fades in after a settled model has rendered its first frame. A corrupt or missing model uses the procedural rover. Context loss or sustained poor rendering returns to the poster; reduced motion uses the poster carousel.
5. Below 1024px, the bootstrap leaves the original poster and native attachment accordion in place. It imports no React/GSAP/Three.js code or model. Resizing to this range unmounts the desktop experience and restores the fallback markup.

Static HTML and small-screen styles must remain: future mobile work will start from them. No JavaScript retains the poster, desktop static cards and native catalogue. Empty poster spacing elements intentionally preserve the existing desktop layout.

## Verification

`npm run test:rover` exercises all five real attachment geometries, fixed docking, stopped working actions, wheel travel, the fixed viewing direction, all five photographic backdrops and their crossfade, trolley cargo, reverse scrolling, undocking, rendering budgets, context loss, synthetic valid/corrupt model loads and retained fallbacks in Chromium with software WebGL. The synthetic model is created inside the test and never published.

`npm run test:startup` performs hard reloads with caching disabled, 200 ms latency, 250 KB/s download and 4× CPU throttling. It checks automatic 3D, desktop poster, 390px, reduced motion, unavailable WebGL and no-JavaScript modes. A test-only capability shim allows SwiftShader to exercise automatic 3D startup; production detection is unchanged.
